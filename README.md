# Альфа · Контекст

Прототип персональной новостной аналитики для руководителей крупного бизнеса. События сопоставляются с признаками компании, ролью пользователя и банковскими материалами. Выводы содержат основания, ограничения и проверяемые ссылки.

**В ленте по умолчанию — реальные новости «Ведомостей» и Банка России; начальные профили компаний учебные.** Синтетические новости и аналитика доступны отдельно во вкладке «Учебные события» и не отражают реальную позицию Альфа-Банка. Деморежим анализа работает без API и использует явно обозначенные правила. Подключение разрешенной LLM включает планирование, анализ и отдельную проверку выводов. Произвольные вопросы требуют LLM; деморежим этого не имитирует.

## Быстрый запуск

Нужны Docker Engine / Docker Desktop с Linux containers и Docker Compose v2.24.4+. Из корня:

```sh
docker compose up --build -d --wait
```

Открыть http://localhost:8080. Первая сборка загружает зависимости. Postgres создается и мигрируется автоматически; данные сохраняются в volume.

| Аккаунт | Пароль по умолчанию | Права |
| --- | --- | --- |
| `demo` | `demo-alfa-2026` | Три компании, импорт, показатели качества |
| `viewer` | `demo-alfa-2026` | Только «Северный металл», без администрирования |

Пароль первоначального создания меняется через `DEMO_PASSWORD`. Изменение переменной не меняет уже созданные учетные записи. Не используйте демопароли на публичном сервере.

```sh
docker compose logs -f api worker
docker compose down
```

`down` сохраняет БД. Не добавляйте `-v`, если данные нужны.

При обновлении кода повторите `docker compose up --build -d --wait`: миграции выполняются до старта API и worker. После перехода на миграцию `0002` ранее созданные разборы без снимка прав нужно запустить заново из ленты; документы и импортированные данные сохраняются.

## Проверочный сценарий

1. Войти как `demo`. Во вкладке «Реальные новости» дождаться обновления источников и открыть разбор статьи «Ведомостей». Профиль компании пока учебный.
2. Проверить факты, условное влияние, полный текст источника и переход на сайт издателя. Если аналитика банка не загружена, его позиция явно отсутствует. Для отдельного учебного сценария о ставке выбрать «Учебные события» и «Северный металл», роль CFO.
3. Переключить компанию на «Торговый контур», роль — казначей. Убедиться, что изменились оценки релевантности и причины отбора.
4. В «Контексте компании» посмотреть происхождение признаков, концентрацию платежей и отсутствующие данные.
5. В «Источники и импорт» добавить ранее не показанную новость с отметкой «Синтетический материал». Вернуться во вкладку «Учебные события», открыть анализ и журнал шагов.
6. Открыть источник из конкретного вывода. Дать обратную связь и проверить ее в показателях качества.
7. Задать вопрос. В деморежиме получить честное сообщение об ограничении; в live — ответ с дополнительным поиском.
8. Войти как `viewer`: другие компании и административные операции недоступны.

## Локальная разработка без Docker

Python 3.13 и Node.js 24. Версии Python-зависимостей зафиксированы в `backend/requirements.lock`, frontend — в `frontend/package-lock.json`.

```powershell
python -m venv .venv
python -m pip --python .venv install -r backend/requirements.lock
./scripts/dev.ps1
```

Во втором терминале:

```powershell
cd frontend
npm ci
npm run dev
```

Открыть http://localhost:5173. API работает на 127.0.0.1:8000, Vite проксирует `/api`. SQLite и встроенный worker предназначены для локальной разработки. В Docker используются PostgreSQL и отдельный worker. Если `venv` не установил pip, команда `python -m pip --python .venv install ...` использует pip системного Python.

## Реальные материалы и модели

1. Скопировать `.env.example` в `.env`. Этот файл исключен из Git.
2. Получить у организаторов CSV компаний, платежей и связей физлиц, PDF банковской аналитики и доступ к разрешенным моделям.
3. Импортировать компании, затем связи; для материалов организатора выключить отметку синтетических данных. Название файла не определяет тип: платежи и физлица различаются по колонкам. Кодировки: UTF-8/UTF-8 BOM/Windows-1251; разделители: запятая, точка с запятой, табуляция. Предполагается одна агрегированная строка на пару плательщик–получатель. Повторы внутри файла возвращаются как ошибка, повторный импорт обновляет связь.
4. Подтвердить единицы `REVENUE_COMPANY` и `PAY_AMT` и период платежей. Демонстрационные суммы заданы в рублях. Обезличенные ID не используются для поиска реальных организаций.
5. Импортировать банковские PDF с датой публикации, выключив отметку синтетического материала. Извлекается текст; сканы распознаются локально Poppler + Tesseract rus/eng. Сохраняются страницы и оригинальный PDF; числа, графики и таблицы требуют сверки с оригиналом. Лимит файла — 64 МБ.
6. Реальные новости автоматически собираются из RSS и страниц статей. Они доступны и настоящим, и учебным компаниям. Синтетические события можно анализировать только на учебных профилях. Анализ реального события не использует синтетические новости и банковские материалы. Ручная загрузка новости и принудительное обновление источника доступны администратору.
7. Установить `DEMO_MODE=false`, HTTPS `LLM_BASE_URL` (включая `/v1`, если его требует провайдер), `LLM_API_KEY`, точные `LLM_ANALYSIS_ID` и `LLM_EXTRACTION_ID` из документации организатора.
8. Указать утвержденные названия моделей и подтвержденные тарифы за миллион токенов. Значения `0` блокируют платные вызовы. Проверить соответствие API ID разрешенной модели у провайдера.
9. Перезапустить `docker compose up -d`. Провести smoke-тест на небольшой новости перед массовой обработкой.

Модели в шаблоне: `Qwen3.6 35B A3B` для анализа и `Gemma 4 26B A4B` для извлечения. В локальном тесте по выбору пользователя все этапы используют **DeepSeek V4.1 Flash**, API ID `deepseek-flash`; провайдер проверен реальными запросами. Первичный порядок ленты рассчитывается объяснимыми правилами. Протокол адаптера — OpenAI-compatible `/chat/completions` с JSON-ответом; это формат протокола, **не использование моделей OpenAI**. Если провайдер выдал другой формат, адаптер нужно сверить с его документацией.

Лимит приложения по умолчанию — 450 ₽/сутки, абсолютный максимум настройки — 500 ₽. В тарифах укажите максимум среди используемых моделей: единый шлюз консервативно считает их по одной ставке. Стоимость атомарно резервируется до вызова; неизвестная стоимость таймаута не возвращается в бюджет. Дата лимита настраивается через `LLM_BUDGET_TIMEZONE`. Этот учет не видит вызовы общего ключа другими приложениями; сверяйтесь с лимитом провайдера. Восстановление задач не отменяет стоимость уже состоявшихся вызовов.

Для начального теста действует **общий потолок 20 обращений к LLM**. После согласования ещё пяти обращений локальный предел `LLM_REQUEST_LIMIT` — **61 суммарно: 56 использованных + 5 новых**, общий денежный потолок — **30 ₽**. В успешном повторе для U_6923 / казначея потрачено 2 запроса и около 1,11 ₽; итог **58/61 и 25,38597 ₽**, осталось 3 запроса. Оба сценария приняты, платные вызовы остановлены. Шаблон оставляет начальное значение 20, абсолютный максимум настройки — 61. Все модели, пользователи, этапы и ошибочные попытки расходуют одну квоту. Счётчик сохраняется в базе и не сбрасывается при перезапуске, смене модели или наступлении полуночи. Квота и максимальная денежная стоимость резервируются атомарно до HTTP; неясный результат таймаута не возвращает попытку. Стоимость — оценка приложения, не выписка провайдера. Результаты, ограничения качества и прямые ссылки для просмотра без новых вызовов — в [журнале DeepSeek](docs/deepseek.md).

Перед первым платным вызовом явно задайте `LLM_TEST_LIMIT_RUB` — общий денежный потолок теста. По умолчанию он равен `0`, и платные вызовы заблокированы. Работает более строгий из дневного и общего денежных лимитов; оценка зависит от подтвержденных тарифов и учета токенов провайдера. Счетчик, остаток запросов и учтенная стоимость доступны администратору в `GET /api/admin/metrics`, поле `llm_allowance`. RSS-сбор не обращается к LLM. Секретный `LLM_API_KEY` хранится только в локальном `.env`, исключенном из Git.

Проверенная настройка самой дешёвой модели прямого API DeepSeek, ограничение thinking и порядок небольшого теста описаны в [deepseek.md](docs/deepseek.md). Число обращений не равно числу разборов: каждый этап агента расходует общую квоту.

`AUTO_FETCH_RSS=true` включен по умолчанию. При первом запуске worker загружает новости сразу, затем обновляет каждый источник через `RSS_REFRESH_SECONDS=1800` секунд после завершения предыдущего сбора. За проход обрабатываются до `RSS_ITEM_LIMIT=50` последних публикаций каждого источника. При сетевой ошибке повторная попытка назначается не позднее чем через 5 минут. Для работы без сети установите `AUTO_FETCH_RSS=false`.

Под переключателем ленты показаны статус и время обновления источников. Открытая лента подхватывает новые события каждые 15 секунд; просмотр разбора не прерывается. Первичная загрузка занимает несколько минут. Состояние расписания хранится в PostgreSQL и сохраняется при перезапуске; одновременные обновления одного источника не дублируют работу.

Для «Ведомостей» извлекаются публичные абзацы статьи, для Банка России — основной текст публикации. В карточке первоисточника показаны время загрузки и полнота: «Текст статьи» либо «Только RSS-аннотация». Если полный текст недоступен, используется явно помеченная аннотация достаточной длины; иначе публикация пропускается с ошибкой в отчете. Закрытые тексты не обходятся. Полный отчет доступен через `GET /api/feeds/status` и ручное обновление в разделе импорта.

## API и устройство

Документация: `/api` маршруты описаны в `docs/openapi.json`; интерактивный Swagger на API `/docs` (внутренний порт 8000). Все изменяющие запросы требуют `X-Alfa-Request: 1`. Авторизация — HttpOnly cookie с серверной сессией на 12 часов.

- `POST /api/auth/login`, `GET /api/auth/me`, `POST /api/auth/logout`
- `GET /api/companies`, `GET /api/companies/{id}/context`
- `GET /api/feed?company_id=…&role=CFO`
- `POST /api/analyses` → `run_id`; `GET /api/runs/{id}` → статус, журнал, результат
- `POST /api/insights/{id}/questions`, `POST /api/insights/{id}/feedback`
- `GET /api/sources/{id}`, `GET /api/sources/{id}/original`, `GET /api/library`
- `POST /api/admin/news`, `/api/admin/import/csv`, `/api/admin/import/pdf`, `/api/admin/feeds/{key}`
- `GET /api/admin/metrics`

Источники являются общим корпусом публичных новостей и предоставленных материалов кейса. Не загружайте в них внутренние документы отдельных клиентов: разграничение доступа по документам не реализовано. Компания, запуск анализа и данные пользователя проверяются на сервере, независимо от интерфейса.

Архитектура и ограничения: `docs/architecture.md`. Развертывание с HTTPS: `docs/deployment.md`. Процедура оценки: `docs/evaluation.md`.

## Проверки

```powershell
cd backend
../.venv/Scripts/python -m pytest
cd ../frontend
npm run build
```

Browser E2E: `npm run test:e2e` при работающем dev-сервере и API; для CI нужны браузеры Playwright (`npx playwright install --with-deps chromium`). По умолчанию тест использует http://localhost:5173; `E2E_BASE_URL` меняет адрес.

CI проверяет backend, TypeScript/сборку и три браузерных сценария после запуска Docker с PostgreSQL. При ошибке браузерной проверки сохраняются скриншоты и trace. Регрессионные проверки покрывают доступ, бюджет, ссылки, поиск, недостающую аналитику, новую новость, идемпотентность и восстановление worker. Метрики Precision@5 и фактической подтвержденности **не считаются достигнутыми без независимой разметки и реальных моделей**.

Не включать ключи, `.env`, пользовательские загрузки и исходные непубличные данные в Git. Публикация онлайн требует сервера, домена и доступов, которые пока не предоставлены.
