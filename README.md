# Альфа · Контекст

Прототип персональной новостной аналитики для руководителей бизнеса: событие → признаки компании → механизм влияния → риски, возможности и возможные действия → источники. Мнение экспертов Альфа-Банка отделено от интерпретации AI.

Состояние на 26.10.2026: [реализация и проверки](docs/completion-report-20261026.md), [каждый пункт PDF](docs/requirements-report.md). Полный отбор `full-feed-v1` готов в коде: все статьи, включая прежние отказы, проходят оценку и проверку, затем модель объединяет порядок. Лента имеет стабильные страницы, а локальный режим — автоматическую обработку. **Новые ответы целевой локальной модели ещё не получены; качество новой генерации не заявляется.**

## Запуск

Нужны Docker Engine/Desktop с Linux containers и Docker Compose 2.24.4+. На чистой копии репозитория без пользовательского `.env`:

```sh
docker compose up --build -d --wait
```

Открыть [кабинет](http://localhost:8080). Миграции выполняются автоматически. Сразу после входа открывается заполненная учебная лента. Раздел **«Готовые примеры»** содержит девять готовых разборов для трёх компаний и трёх ролей; ключ LLM не нужен. [Фикстуры и их происхождение](backend/fixtures/README.md) входят в Git и Docker-образ. Это синтетические учебные сценарии, а не реальные новости, мнения банка или ответы DeepSeek. Произвольный ответ на вопрос требует LLM.

| Логин | Пароль первоначального создания | Права |
| --- | --- | --- |
| demo | demo-alfa-2026 | Три профиля, импорт и административные показатели |
| viewer | demo-alfa-2026 | Один учебный профиль, без импорта и журнала агента |

Для существующего локального снимка кейса:

```powershell
.\scripts\start-preview.ps1
```

[Preview](http://127.0.0.1:8081/) сохраняет свои тома. По умолчанию ключ и URL модели пустые, RSS выключен. Администратор может включить RSS и модель через настройки; эти изменения сохраняются при перезапуске. При первом запуске с пустыми томами доступны только учебные данные. Восстановленный локальный снимок также содержит реальные материалы и исторические ответы DeepSeek; оценки прежнего подключения явно помечены.

## Что проверить

1. Войти, выбрать компанию и роль CEO/CFO/казначей. Изменяются основания и порядок.
2. Переключить «Для моей компании» / «Все материалы». Поиск и тематический фильтр сохраняют персональный порядок; «Показать ещё» продолжает тот же снимок.
3. Открыть контекст: происхождение признаков, неизвестные единицы и рыночная доля, поиск по всем доступным платёжным связям.
4. В разборе сопоставить факты, мнение банка с датой/страницей и условные выводы AI. Перейти к источнику и оригинальному PDF.
5. Добавить учебную новость через «Источники и импорт», открыть её разбор, оставить отзыв, задать вопрос. Демо честно сообщает, что свободный ответ без модели недоступен.
6. Войти как viewer и проверить отсутствие других компаний и административных действий.

Подробный [сценарий демонстрации](docs/demo.md). [Swagger](http://localhost:8080/api/docs) и [сохранённый OpenAPI](docs/openapi.json).

## Архитектура и данные

React/TypeScript, FastAPI, отдельный Python worker и PostgreSQL. База хранит профили, источники, полнотекстовый индекс, очереди, проверенные результаты, снимки ленты и аудит. [Схема и контракты](docs/architecture.md).

Настоящие RSS/HTML-адаптеры Банка России и «Ведомостей» получают открытые тексты. Ограниченные страницы остаются ограниченными источниками с отметкой полноты. Опубликованный текст не обрезается перед LLM: техническое переполнение контекста становится явной ошибкой.

Импорт CSV определяет тип по колонкам, поддерживает UTF-8/BOM/Windows-1251 и распространённые разделители, проверяет ключи и повторы. Связь платежа не доказывает договор поставки. ФТС не раскрывает валюту и направление торговли. Суммы, период, объём рынка и условия кредитов не выдумываются. [Материалы кейса и импорт](docs/case-data.md).

PDF банка: текст/OCR, страницы, уверенность распознавания и оригинал. Графики и таблицы не считаются проверенными числовыми источниками. Неизвестная дата и историческая оценка отображаются отдельно.

## Модели и конфигурация

Переменные перечислены в [.env.example](.env.example); секретный `.env` исключён из Git. Названия моделей сверяются с разрешённым списком из PDF, точный ID и соответствие весов подтверждает оператор.

**В интерфейсе:** войти администратором → «Настройки LLM» → выбрать локальный/удалённый API, указать адрес, токен и ID модели. Для DeepSeek есть кнопка заполнения параметров Flash. Токен локального сервера необязателен. Дополнительные поля позволяют указать отдельную модель извлечения, таймаут, размер контекста и версию весов. Для удалённого API задаются тарифы и лимиты; для локального денежной квоты нет. Включить «Разрешить вызовы LLM» и сохранить. Проверочного запроса при сохранении нет. Отдельный флажок «Автоматически обрабатывать новые новости» разрешает фоновые вызовы для выбранных компаний.

Настройки сохраняются в отдельном серверном томе `runtime_settings`, применяются API и worker без перезапуска и имеют приоритет над `.env`. Токен не возвращается в GET-ответах, журнале или браузерном хранилище; поле после сохранения пустое. При смене адреса или типа подключения сохранённый токен не переносится. Для удаления есть флажок; «Вернуть настройки из .env» удаляет серверные переопределения, но не сбрасывает расход API. Пока в очереди есть анализы или отбор, смена подключения отклоняется. Уже выполняющаяся задача использует единый снимок настроек.

Окружение остаётся альтернативой: `LLM_BASE_URL`, `LLM_API_KEY`, точные `LLM_ANALYSIS_ID`/`LLM_EXTRACTION_ID`, разрешённые названия моделей и `DEMO_MODE=false`. После изменения окружения пересоздать API и worker с теми же Compose-дополнениями. Сохранённые через интерфейс настройки нужно предварительно сбросить, чтобы окружение снова стало источником конфигурации.

Для будущего локального сервера использовать [compose.local-llm.yaml](compose.local-llm.yaml) и [инструкцию подключения](docs/local-llm.md). Модель и веса этим проектом не устанавливаются. В локальном режиме нет денежного потолка, тестовой квоты обращений и клиентского `max_tokens` по умолчанию. Сохраняются технические таймауты, контекст, продление владения задачей и конечное число восстановлений.

Удалённый тестовый API имеет явные тарифы, резерв максимальной стоимости, лимит запросов и общий бюджет. Нулевые тарифы/бюджет запрещают платные вызовы. Автоматический платный отбор включается отдельным флажком и охватывает материалы, импортированные или изменённые после включения: оценка трёх ролей и семантическая самопроверка. Старый архив не отправляется автоматически; сравнительная перестройка всей ленты запускается отдельной кнопкой. Один пакет содержит до пяти целых статей для компании. Уже завершённые и ошибочные задачи автоматически не повторяются. При недостатке бюджета вызов блокируется шлюзом; RSS продолжает работать. Подробный разбор пользователь запускает из карточки.

Локальная модель автоматически обрабатывает весь накопленный корпус, включая полное сравнительное упорядочивание, без денежных квот. Окружение для локального режима: `AUTO_PERSONALIZATION=true`, `NEURAL_RANKING_WORKER=true`, начальные профили — `ACTIVE_COMPANY_IDS`.

При HTTP 402 (нет средств у провайдера) новые обращения приостанавливаются, причина показана в ленте. После пополнения сохранить «Настройки LLM» для возобновления; отклонённые предварительные оценки выбранных компаний возвращаются в очередь. Попытка остаётся в счётчике обращений, локальный денежный резерв за явно отклонённый запрос освобождается. При неизвестном исходе, например таймауте, резерв сохраняется.

Первый проход RSS в пустой БД рассматривает до `RSS_ITEM_LIMIT=50` записей **из каждого** выбранного источника (до 100 при двух источниках). Это текущие RSS-ленты, без обхода архива сайта. Лимит в окружении — 1–200 на источник; фактическое число зависит от размера RSS, ошибок загрузки и дедупликации. Для каждой записи загружается статья; если она недоступна, достаточная RSS-аннотация сохраняется с отметкой неполноты. По умолчанию повторный проход — через 30 минут.

`LLM_MODEL_REVISION` меняют при обновлении весов/настроек с прежним ID. `LLM_CONTEXT_CHARACTERS` — технический предел входного пакета, не денежная квота. `JOB_LEASE_SECONDS` задаёт возобновляемый срок владения задачей.

## Откуда берутся новости

В обычном `compose.yaml`, в том числе с production-дополнением, `AUTO_FETCH_RSS=true` по умолчанию: worker начинает загрузку после запуска API и повторяет её раз в `RSS_REFRESH_SECONDS=1800` секунд. За одно обновление берётся до `RSS_ITEM_LIMIT=50` элементов каждой ленты. Ошибки источника приводят к повтору через 300 секунд или раньше, если основной интервал короче. Сохранённое расписание учитывается при перезапуске.

Список источников сейчас задан в `FEEDS` и `FEED_NAMES` в [ingestion.py](backend/app/ingestion.py): Банк России (`https://www.cbr.ru/rss/RssPress`) и «Ведомости» (`https://www.vedomosti.ru/rss/news`). В интерфейсе «Источники и импорт → RSS-источники» можно вручную обновить один из них. Добавление нового издателя требует изменения конфигурации источников в коде, разрешённых доменов и, при необходимости, HTML-адаптера; произвольный URL из интерфейса не добавляется.

В preview и изолированной проверке `AUTO_FETCH_RSS=false` по умолчанию. Администратор может изменить это без перезапуска: **«Источники и импорт» → «Автообновление новостей»**, выбрать источники, интервал и сохранить расписание. Из ленты туда ведёт «Настроить автообновление». После включения выбранные источники проверяются в течение 10 секунд; затем действует заданный интервал. Начатая загрузка завершается при выключении. Настройки сохраняются в серверном томе вместе с подключением модели, но управляются независимо: сброс настроек LLM не выключает расписание.

Парсинг не вызывает LLM. Появление новой статьи в хранилище не означает готовую персональную оценку: автоматический нейросетевой отбор включается отдельно для настроенной локальной модели. Для ещё не обработанного профиля интерфейс сообщает, что подборка не готова, вместо ложного вывода об отсутствии релевантных новостей. На замороженном preview виден режим сохранённых данных; карточка отдельно сообщает, есть ли готовый разбор. Чтение статьи не требует модели.

Лента по умолчанию отсортирована по релевантности. Переключатель «Порядок событий» предлагает новые или старые публикации первыми; порядок применяется ко всей подборке до пагинации. «Прямая связь с профилем» и «Условная применимость» отражают сохранённые оценки модели, а не доказанный финансовый эффект. Пояснение доступно в ленте; использованные признаки и цитаты — в основаниях карточки. Начало статьи показывается целыми предложениями, полный доступный текст открывается отдельно. Сокращения источника поясняются без изменения оригинала и доказательств.

## Проверки и разработка

Python 3.13, Node.js 24; зависимости: `backend/requirements.lock`, `frontend/package-lock.json`. Для разработки: создать `.venv`, установить Python-зависимости, выполнить `scripts/dev.ps1`; во втором терминале `cd frontend`, `npm ci`, `npm run dev` (порт 5173).

```powershell
# Из backend:
..\.venv\Scripts\python.exe -m pytest -q
# Из frontend:
npm run build
# Из корня, предварительно остановив preview на 8081:
.\scripts\verify-local.ps1
```

Изолированная проверка создаёт чистый Docker-проект: миграции, браузерный сценарий, права, очередь после перезапуска, восстановление БД и бинарного файла. Ключ и URL LLM принудительно очищены. Тестовые тома сохраняются, основной 8080 не меняется.

[Оценка качества](docs/evaluation.md): 30 событий разработки + 20 новых контрольных, 450 AI-меток; старые метки сохранены. P@5 ≥0,8 и фактическая подтверждённость ≥95% — внутренние цели, не пороги из PDF и не достигнутые результаты.

Внешнее развёртывание ждёт сервера и домена. [Инструкция](docs/deployment.md). Доступ жюри пока не выдан по решению владельца. [Сторонние компоненты](THIRD_PARTY_NOTICES).
