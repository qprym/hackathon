# Независимая оценка качества

Цели: Precision@5 ≥0,8 для каждой компании/роли; ≥95% фактических утверждений подтверждаются основаниями. Это цели, не заявленные результаты. Разметку выполнит владелец проекта.

## Готовый набор

`data/private/evaluation-20261024.json`: 50 новых реальных событий, 30 development / 20 holdout, три компании (U_26491, U_989, U_6923), три роли, 450 пустых оценок. Включены тексты, даты, ссылки, полнота источника, снимки профилей и фиксированная дата ранжирования. Скоринг и ответы модели не показываются.

Исключены прежние запуски, старый evaluation.json, общие документы и одинаковые нормализованные заголовки. Эксперту нужно проверить семантически близкие сообщения и оставить их в одном split. Файлы кейса остаются в игнорируемой data/private; существующие файлы экспортер не перезаписывает.

## Как разметить

1. Открыть [форму](http://localhost:8080/review.html) из «Качество и бюджет», выбрать evaluation-20261024.json, указать имя/псевдоним.
2. Начать с development. Для каждой компании и роли прочитать источник и профиль.
3. Поставить 0 — нет применимой связи; 1 — полезная косвенная связь; 2 — приоритетное событие с конкретным механизмом. При недостатке данных оставить пусто, добавить комментарий.
4. Сохранить прогресс в JSON. Закрытие окна его не сохраняет; продолжить можно из скачанного файла.
5. После фиксации ранжирования разметить holdout. Не использовать его оценки для настройки той же версии.

Форма читает файл только в памяти браузера, не обращается к API/LLM, не исполняет HTML из источников. Тест проверяет экспорт оценки без заполнения других ячеек.

Оценщик использует сохранённые профили и дату, возвращает версию правил и ID top-5:

```powershell
.\.venv\Scripts\python.exe scripts/evaluate.py --data data/private/evaluation-20261024.reviewed.json --split development
.\.venv\Scripts\python.exe scripts/evaluate.py --data data/private/evaluation-20261024.reviewed.json --split holdout
```

Без полных меток, автора/даты — incomplete, код 2. Сейчас в holdout 180 пустых оценок. Старый синтетический events.json остаётся учебной заготовкой; для воспроизводимой оценки нужен экспорт версии 2.

## Утверждения

`evaluation-20261024.claims.json` содержит 11 утверждений двух опубликованных live-разборов: четыре фактических утверждения и семь сценариев. Открыть той же формой. supported=true — достаточно оснований, корректны ограничения; false — ошибка или недостаток оснований, причину записать в комментарий. У сценария проверить предпосылки; в долю подтверждённых фактов он не входит.

Ответы исторические, помечены outdated и не подтверждают качество новой financial-v3. Оценщик разделяет текущие и исторические версии; одна историческая разметка не даёт target_met=true.

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_claims.py data/private/evaluation-20261024.claims.reviewed.json
```

Новые live-результаты на holdout и уточняющие вопросы требуют отдельного бюджета. Экспорт, форма и оценщики не делают платных вызовов.

## Новый экспорт

```powershell
docker compose run --rm --no-deps -v "${PWD}:/workspace" api python /workspace/scripts/export_evaluation.py --companies U_26491 U_989 U_6923 --exclude /workspace/data/private/evaluation-20261024.json --output /workspace/data/private/evaluation-next.json
```

После изменения модели/правил/промптов фиксировать версии, сохранять прежние оценки и собирать новый holdout. Отдельно проверять удаление банковского материала, изменение признака, противоречивый источник, старую дату, OCR и инструкции внутри новости. Регулярная экспертная оценка описана как процесс; автоматическое расписание не создано.
