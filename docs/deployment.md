# Онлайн-демо

Понадобятся Linux-сервер, Docker Compose v2.24.4+, домен с A/AAAA-записью на сервер и открытые 80/443. DNS и сертификаты обслуживает Caddy. Образы и зависимости скачиваются при первой сборке. Сами LLM работают у провайдера, GPU на сервере не нужен.

1. Скопировать репозиторий на сервер и `.env.example` в `.env`.
2. Установить сильные `DEMO_PASSWORD` и `POSTGRES_PASSWORD`. В `DATABASE_URL` прописать тот же пароль PostgreSQL, URL-кодируя спецсимволы. Пароль demo применяется только при первом создании.
3. Задать `DOMAIN=your-host.example`, `COOKIE_SECURE=true`, `ALLOWED_ORIGINS=https://your-host.example`.
4. Оставить `DEMO_MODE=true` для честного демонстрационного показа без API либо настроить разрешенный LLM-провайдер по README.
5. Выполнить:

```sh
docker compose -f compose.yaml -f compose.production.yaml up --build -d --wait
```

6. Проверить `/api/health`, вход, анализ новости, источники, вопрос, logout, права `viewer`. Убедиться, что браузер получает HTTPS cookie и что порты БД/API недоступны извне.

Приложение не публикует PostgreSQL и API на хост. В production прямой порт web сбрасывается, доступ идет через Caddy. Администраторские права нужны только организаторам демо; посетителям выдавайте `viewer`.

## Сопровождение

Резервная копия: `docker compose exec -T db pg_dump -U alfa alfa > backup.sql`. Перед изменением версии сохранить backup; применять миграции одноразовым сервисом `migrate`. Старые миграции не редактировать после сдачи.

Проверять `/api/health`, состояние worker, число ошибок, очередь, бюджет и обратную связь. После изменения модели/промпта запускать тесты и независимую оценку. Не выводить `.env` или полный compose config с секретами в публичные логи. Для отката сохранить прошлый Git tag и совместимую резервную копию БД.

Реальный сервер, домен и доступы не предоставлены. Этот документ и конфигурация подготавливают публикацию, но сами по себе не подтверждают онлайн-развертывание.
