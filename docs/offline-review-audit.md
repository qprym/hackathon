Новых запросов к DeepSeek не было. Счётчик до и после работы: **39 из 40**, учтённая стоимость **15,10368 ₽**. Старые запуски и их статусы не изменены; отклонённые ответы не опубликованы задним числом.

Это результаты сверки, выполненной в рамках разработки, без независимой экспертной разметки. Классифицировались замечания, а не целые ответы. Наличие ложного замечания не означает, что остальные выводы черновика верны.

## Где ошибается генератор

1. **Подмена продукта.** В `75c1bf14`, попытка 0, розничные ставки названы ориентиром доходности депозита компании. Оговорка «не корпоративный продукт» не исправляет такой перенос.
2. **Исторические сведения превращаются в текущие условия.** В `28ae4466` и `edd3058a` сентябрьские 14% попадают в заголовок и базовый финансовый сценарий октябрьского события. Следует отдельно назвать дату исторического материала и запросить актуальные условия.
3. **Условное предложение содержит недоказанную предпосылку.** «Если высокая стоимость фондирования сохранится» уже подразумевает высокую стоимость. Метка `assumption=true` этого не доказывает. Корректнее: «Если новая корпоративная котировка окажется выше заложенной в план, пересчитать расходы на предстоящие сделки; действующие договоры проверить отдельно».
4. **Источнику приписывается иной прогноз.** Неопределённость на IV квартал в банковском фрагменте не означает смягчение политики в IV квартале.
5. **Привязки признаков неполны.** Лизинг упоминается, но указан только кредитный признак. Значение лизингового признака есть в полном профиле; оно должно быть связано именно с утверждением о лизинге.
6. **Механизм влияния не объяснён.** Количество контрагентов и концентрация платежей сами по себе не доказывают ограниченную гибкость, а замедление зарплат не объясняет последствия новости о ставках без дополнительной связи.

Компания и её продукты передавались модели. Проблема не сводится к отсутствующему контексту: часть ошибок возникает при использовании имеющегося контекста, часть — из-за реально неизвестных условий сделок.

## Где ошибается проверяющий

- `09069375`, попытка 0, замечание 1: утверждает, что у вывода нет признаков кредита и лизинга. Оба ключа уже приложены. Новость не должна доказывать наличие продукта у клиента.
- `28ae4466`, попытка 0, замечание 1: требует предупреждение о розничном характере ставок, хотя оно есть в `limitations.0` и других разделах.
- `a7fabe1f`, попытка 1, замечание 0: сравнивает разные выпуски мониторинга, 13 и 21 октября, как противоречие. Утверждение цитирует выпуск от 21 октября; отличающиеся значения за другую дату его не опровергают.
- `43aace67`, попытка 1, замечание 1: требует 13,06% в каждом фрагменте. Число подтверждается E1, методика и состав банков — соседним E2 того же документа; текст уже упоминает состав выборки.

Отдельная группа — требования убрать правдивые ограничения размерности данных и возраста материалов. Это редакционные предпочтения, а не основание объявлять разбор недостоверным. При этом действительно нерелевантный источник нельзя использовать для доказательства причинности: наличие лишней ссылки и ложная атрибуция — разные дефекты.

Смешанные замечания разобраны по частям. Например, в `09069375` показатели платёжных связей имеют основания в `feature_keys`, но вывод об ограниченной гибкости из них не следует. В `a7fabe1f` после уточнения даты сценарий всё ещё содержит слова «может остаться повышенной»: условность не устраняет предпосылку о ранее установленной корпоративной стоимости.

Полная разметка всех 23 замечаний — [offline-review-cases.json](offline-review-cases.json). Индексы попыток и замечаний начинаются с нуля. SHA-256 каждой исходной строки защищает от применения разметки к другому ответу.

## Исправления в коде

| Причина | Изменение | Проверка |
|---|---|---|
| Генератор и проверяющий использовали общую инструкцию | Отдельная инструкция проверки: дата, продукт, предпосылка сценария, атрибуция, совместные основания | Проверяющий получает отдельный контракт, а не указания переписать записку |
| Свободный список замечаний без проверяемого адреса | Вердикт для каждого пункта: `item_id`, дословный фрагмент, причина, категория, цитаты, признаки, исправление | Пустые, неполные, повторные и противоречивые вердикты блокируются |
| Игнорирование приложенных признаков | Основания компании разрешаются по точному `item_id`; заявленные отсутствующими ключи сопоставляются с приложенными | Уже приложенный признак не может быть указан в `missing_feature_keys`; неверная проверка повторяется |
| Потеря связи между частями документа | Стабильные группы документов, отдельные даты, все найденные фрагменты в пакете проверки | Соседние фрагменты проверяются совместно; нецитируемые основания доступны для проверки противоречий |
| Любое редакционное пожелание блокировало ответ | Отдельные `editorial_notes`; содержательные ошибки и неопределённость остаются блокирующими | Редакционная заметка не отменяет отрицательный вердикт |
| Исправление заново генерировало весь текст | Точечный `InsightPatch` только для отклонённых пунктов | Нельзя менять остальные пункты, неизвестные адреса или удалить весь impact/facts; затем проверяется весь результат |
| Сломанная проверка портила корректный черновик | При нарушении протокола повторяется проверка сохранённого текста | Тест фиксирует последовательность: один синтез, две проверки |
| Банковские фрагменты попадали в исходный список новостей из-за общей ссылки на список | Отдельная копия списка; facts live-разбора ограничены исходными документами события | Банковская история не может пройти как факт новой новости |
| Дата публикации позволяла случайно подтвердить число | Отдельное сопоставление дат, месяцев, лет и количественных значений | 11 сентября не подтверждает ставку 11%; полная дата не подтверждается одним совпавшим годом |
| Ошибки разделителей чисел | Сохранены знак и точное значение, диапазоны не склеиваются в тысячи | Проверены 91–180, −5%, 1 000 и несоответствующие значения |
| Меткой предположения можно было обойти числовую проверку факта | Для facts и bank_view запрещён `assumption=true` | Локальный отказ до платной проверки |
| После сбоя нельзя восстановить проверяющий запрос | Сохраняются точные пакеты синтеза, исправления и проверки до вызова, а также структурированный ответ проверяющего | При ошибке/усечении остаются доказательства и привязки, без ключа и внутренних рассуждений модели |

Ключ кеша обновлён до `prompt-v12`. Старые результаты доступны по прежним адресам; они не переобозначаются как прошедшие новую проверку. Квота, денежный потолок и отсутствие автоматических HTTP-повторов сохранены.

Неправильное замечание проверяющего **не превращается автоматически в положительный вердикт**. Ошибка протокола приводит к повторной проверке в существующем лимите попыток, а при неустранённой проблеме — к `insufficient`. Подтверждение смысла цитаты по-прежнему требует проверки моделью: точное наличие строки само по себе не доказывает вывод.

## Как воспроизвести без платных запросов

Из корня проекта в PowerShell:

```powershell
Push-Location backend
..\.venv\Scripts\python.exe -m pytest tests -o addopts='' -q
..\.venv\Scripts\python.exe -m app.replay_reviews --input-dir ../data/private --annotations ../docs/offline-review-cases.json --output ../data/private/offline-review-repeat.json
Pop-Location
```

Для повторного запуска отчёта выберите новое имя `--output`: существующие файлы намеренно не перезаписываются. Тесты используют отдельную SQLite-базу и блокируют реальный HTTP-вызов LLM. Команда `replay_reviews` не импортирует шлюз провайдера, конфигурацию или БД; читает только сохранённые JSON и разметку.

Выполнено **89 тестов**, все прошли. Сборка API/worker успешна. В локальных сервисах установлен исправленный код; очередь анализов пуста. Фактический повтор сохранённых ответов: `data/private/offline-review-final.json`. Приватные ответы и фрагменты материалов не добавлены в Git.

У старого failed-запуска `28ae4466` не сохранился полный пакет источников и контекста. Его два черновика и один ответ проверяющего доступны, но локальная перепроверка полного набора оснований честно помечена `missing`. Для остальных восьми черновиков основания восстановлены только из результата того же запуска и списка ID соответствующей попытки; это не объявляется точной копией старого HTTP-запроса.

Офлайн-повтор подтверждает исходный локальный отказ `edd3058a/0`: число 4 не имеет правильной ссылки. Первый черновик `75c1bf14` дополнительно не соответствует уже введённой ранее обязательной маркировке сценариев. Отсутствие локальных ошибок у остальных черновиков не означает смысловой достоверности: новый платный проверяющий их не оценивал.

**Граница результата:** исправления и защита от регрессий проверены локально. Качество нового протокола на реальном DeepSeek пока не измерено; успешный live-разбор, Precision@5 и фактическая точность не заявляются. Новые платные прогоны не проводились.
